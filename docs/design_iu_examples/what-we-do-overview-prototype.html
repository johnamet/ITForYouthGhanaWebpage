Pathways

From first exposure to longer-term opportunity

The portfolio genuinely branches, and it branches unevenly: three initiatives bring learners in, two build capability, two put it to work, and one carries the argument outward. The column widths follow that distribution rather than smoothing it into four equal cards.

Prototype notes

What these two interactions decide

The orbit is the capsule evolving, not repeating

The homepage hero is a large dark capsule holding one photograph at a time. Here the same underlying idea appears at a completely different scale: eight small circles, and the one nearest the pointer grows rightwards into a capsule while its circle stays exactly where it was. The circle is not swapped for a capsule, it becomes the capsule's leading lobe, which is the same geometric premise as the hero and a different object on screen.

Proximity uses the same falloff as the existing arc prototype, so the two feel related: scale rises as the pointer closes, and the nearest node within a short radius opens. Every node is a real button, so click toggles and keyboard focus opens. Below 820px the proximity behaviour is switched off entirely and the row becomes a stack of already-open capsules, because a proximity effect on a touch screen is a broken version of a pointer idea rather than a smaller one.

The pathway is a tree, and the tree is uneven on purpose

The current page renders the four stages as four equal cards in a four-column grid. That says the stages are the same size, which is not true, and it never shows which initiative belongs to which stage even though the copy names them.

This version makes the structure the layout. Columns are 3fr 2fr 2fr 1fr, matching Discover holding three initiatives, Develop two, Apply two, and Amplify one, and every stage fans out to its actual initiatives as named branches carrying that initiative's own accent colour. The asymmetry is the information. Amplify being a single narrow column is the honest picture of the portfolio, not a gap to be padded.

This is also the case for not using the capsule. The branches are small labelled pills rather than capsules, because eight more capsules on the same page directly under the orbit would be the rerun the brief warns about. The tree earns a different form.

Two notes for the implementation

The shrink-to-make-room behaviour uses :has() here because a prototype has no state to read. In React it should be a class driven by the open index instead, which is both more robust and one less browser-support question. The measured widths are the constraint to preserve: the row must fit its column in both states, which is 1086px at rest and 1082px with one node open inside a 1100px measure.

Proximity is gated on (min-width: 821px) and (hover: hover) rather than width alone, so a touch laptop does not get a pointer-only interaction it cannot drive.

All eight initiative names, taglines, accent colours and photographs are the real ones from lib/content/site-config.ts. The stage groupings are the four pathwayCards exactly as written. Implementing this needs one content-model addition: the pathway cards do not currently link to the initiatives they describe, so the grouping lives only in prose. That is called out for a decision rather than guessed at.
