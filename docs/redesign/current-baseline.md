## 4. Layout, typography and token state

### The token set

`app/globals.css:5-29` defines one `:root` block with 20 custom properties:

- **Colour (12):** `--color-primary #1E72BA`, `--color-primary-dark #0152BE`,
  `--color-primary-light #E8F1FA`, `--color-accent #D70B52`,
  `--color-accent-dark #B00944`, `--color-text #1A1A1A`,
  `--color-text-muted #5C6672`, `--color-bg #FFFFFF`, `--color-bg-alt #F7F9FC`,
  `--color-border #D8E5F2`, `--color-card #FFFFFF`,
  `--color-on-dark-muted rgba(255,255,255,0.82)`.
- **Type (2):** `--font-heading`, `--font-body`.
- **Radius (4), split by role:** `--radius-control 0.375rem`,
  `--radius-media 0.75rem`, `--radius-panel 1.5rem`, `--radius-capsule 999px`.
- **Spacing (1):** `--section-space: clamp(4.5rem, 8vw, 8rem)`.
- `color-scheme: light`. The site is light-only; there is no dark palette.

`tailwind.config.ts:20-40` mirrors the colours as a `brand.*` scale, and
`:44-50` mirrors the radii as `rounded-control / media / panel / capsule`.

**The colours are declared twice**, as CSS custom properties and again as
literal hex in the Tailwind theme. `--color-primary` and `brand.primary` are
both `#1E72BA` today. Nothing keeps them in step. That is the single largest
drift risk in the token system: a designer changing `:root` will not move any
`bg-brand-*` utility, and there are far more `bg-brand-*` call sites than
`var(--color-*)` ones.

`tailwind.config.ts:53-58` adds a section spacing scale
(`section-sm/md/lg/xl`, 3.5 / 5 / 7 / 9rem) that duplicates the single
`--section-space` clamp in CSS. Two spacing systems, neither dominant.

The file header at `tailwind.config.ts:1-6` still reads "Merge this with your
existing tailwind.config.ts", which means the config was pasted from a snippet
and never cleaned up.

## 5. Content flow: how a public page gets its data

### The three-layer shape

```
lib/content/*.ts   (static seed, checked into the repo, always present)
        |
lib/cms/*.ts       (Firestore reader; merges the document over the seed)
        |
app/(public)/**/page.tsx   (server component, awaits the reader)
        |
components/**      (pure presentation, receives data as props)
```

**Verified fact.** Every public `page.tsx` is an async server component that
calls `getCms*` and passes the result down as props. No page component reaches
into Firestore itself. `app/(public)/page.tsx` is five lines and delegates
everything to `components/home/homepage-sections.tsx`.

### The exact merge functions

| Function | File | Behaviour |
| --- | --- | --- |
| `getAdminFirestore()` | `lib/firebase/admin.ts` | returns `null` when Firebase is unconfigured; every reader treats `null` as "use the seed" |
| `getDocField<T>(data, path)` | `lib/cms/homepage.ts:34-46` | dotted-path lookup into a Firestore document, `undefined` when absent |
| `resolveCmsArray<T>(value, seed)` | `lib/cms/fallback.ts:22-25` | returns the seed when the value is not an array **or is an empty array** |
| `resolveCmsValue<T>(value, seed)` | `lib/cms/fallback.ts:31-33` | `value ?? seed` |
| `mergeSitePage(fallback, data)` | `lib/cms/site-pages.ts:85-111` | field-by-field `?? fallback`, with 24 optional string fields listed at `:56-79` and 7 array fields at `:86-92` |

`resolveCmsArray` is load-bearing and its reasoning is documented in the file
header (`lib/cms/fallback.ts:1-20`): an earlier `?? []` turned a missing field
into an empty array, which passed `Array.isArray` and silently deleted the
homepage's join-the-movement cards. **An empty array means unconfigured, not
deliberately empty.** Sections are hidden with `active: false` on the item.
`lib/cms/fallback.test.ts` locks this in.

Coverage as measured by `scripts/cms-coverage.mjs`: 60 readers, 19 routes with
full coverage, 9 partial, 4 with none. The four with none are the `/programs/*`
family. See `docs/audit/cms-coverage-map.md`.

## 6. Course integration: `/programs/*` and `/apply-for-training/courses/*`

**Verified fact: yes, both hit a live external API.** They hit the same one, by
two different code paths, with different fallback behaviour.

### The endpoint

`lib/api/courses.ts:3`:

```
const DEFAULT_COURSE_API_ENDPOINT = "https://papi.itforyouthghana.org/api/courses";
```

Resolved at `lib/api/courses.ts:5-11` from, in order,
`process.env.COURSE_API_ENDPOINT`, `process.env.NEXT_PUBLIC_COURSE_API_ENDPOINT`,
then that default, with trailing slashes stripped. It is a real production host,
not a stub.

### The two modules

| Module | Functions | Fallback when the API returns nothing |
| --- | --- | --- |
| `lib/api/courses.ts` | `getCourseCatalog()` (`:70`), `getCourseBySlug(slug)` (`:101`) | **none.** `getCourseCatalog` returns `[]` on a non-OK response (`:77`), on `success === false` (`:82`), and on any thrown error (`:97`) |
| `lib/api/training.ts` | `getTrainingCatalog()` (`:22`), `getTrainingCatalogMixed(cmsCourses)` (`:31`), `getCourseBySlugMixed(slug, cmsCourses)` (`:55`) | **three-tier.** live API, then CMS `page.courses`, then `seedTrainingCourses` from `lib/content/training-config.ts` |

`getCourseBySlug` (`lib/api/courses.ts:101-122`) does have a second chance: on a
failed per-slug fetch it falls through to `getCourseCatalog()` and searches that.
But if the catalogue call also fails it returns `null`, and there is no seed
behind it.

`getTrainingCatalogMixed` (`lib/api/training.ts:31-53`) merges by slug into a
`Map`, so **CMS entries override live API entries on a slug collision**
(`:49-50`, CMS written second). `sortCourses` (`:6-20`) orders by `startDate`
with undated courses last, then alphabetically.

### Which route uses which

| Route | Data call | Behaviour when the API is down |
| --- | --- | --- |
| `/apply-for-training/courses` | `getTrainingCatalogMixed(page.courses)` (`app/(public)/apply-for-training/courses/page.tsx:24`) | falls back to CMS then seed; **page still shows courses** |
| `/apply-for-training/courses/[slug]` | `getCourseBySlugMixed(params.slug, page.courses)` (`.../[slug]/page.tsx:37-39`) | falls back to CMS then seed |
| `/programs` | `getCourseCatalog()` (`app/(public)/programs/page.tsx:7`) | empty array; renders the "not available right now" state at `components/programs/programs-overview.tsx:47-53` |
| `/programs/[category]` | `getCourseCatalog()` then a client-side `slugify` filter (`.../[category]/page.tsx:18-19`) | same empty state |
| `/programs/[category]/[courseId]` | `getCourseBySlug()` (`.../[courseId]/page.tsx:11`) | `null`, handed to `CourseDetailCard` with a `fallbackTitle` derived from the slug |
| `/programs/course/[courseSlug]` | `getCourseBySlug()` (`.../[courseSlug]/page.tsx:11`) | identical to the row above |

All six routes declare `export const dynamic = "force-dynamic"` on line 1, so
none of them is statically generated. The fetches themselves set
`next: { revalidate: 300 }` (`lib/api/courses.ts:74`, `:104`), which is
five-minute ISR caching of the upstream response inside a dynamic render.

There is also an internal proxy, `app/api/courses/route.ts`, a four-line `GET`
that returns `getCourseCatalog()` as `{ success: true, data }`. **Nothing in
`app/` or `components/` fetches `/api/courses`.** It exists for external
consumers or is dead; it cannot be removed without checking outside this
repository.

### The consequence for the redesign

`/programs/*` is the only route family with **no CMS coverage and no seed
fallback**. An editor cannot change a word on it, and if `papi.itforyouthghana.org`
is unreachable the page renders a heading and an apology. `/apply-for-training/courses`
is the same content served properly. That is the substance of the duplicate-route
problem in section 8.

## 8. Risks and contradictions

Ordered by how much they can cost the redesign. Each is a **verified fact**
unless marked otherwise.

### R1: Three routes serve one course detail page, with no canonical (high)

`/programs/[category]/[courseId]/page.tsx:11-16`, `/programs/course/[courseSlug]/page.tsx:11-16`
and `/apply-for-training/courses/[slug]/page.tsx:37-46` all render

all three with a canonical, redirect `/programs/*` into `/apply-for-training/courses/*`,

is only as good as its detector. Re-run `scripts/generate-audit-docs.mjs` before
citing them; the media-inventory file predates this fix.
